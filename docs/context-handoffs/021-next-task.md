# 021 — 三个小程序统一身份接入与知识库权限

更新时间：2026-08-13

## 本轮完成

- 产品编码器、销售提成、企业知识库已由 Nginx `auth_request` 接入工作台同源会话与 BFF 应用岗位校验。
- 未登录访问三个应用入口或其 API 均返回 401；工作台管理员登录后，三个入口均返回 200。
- 企业知识库已登记为工作台应用 `knowledge-base`，对全部已定义岗位开放基础访问。
- 用户确认的知识库权限：所有已登录用户可查看、新增、评论、更新、停用资料；仅管理员可新增、编辑、停用资料分类。
- 知识库服务端已强制拦截非管理员对 `/api/v1/document-types` 的非 GET 写入（直连本机测试返回 403）。前端也会隐藏非管理员的分类管理控件。
- 知识库 API Docker 端口已改为仅监听 `127.0.0.1:4180`，防止通过公网 4180 绕过工作台权限。

## 验证结果

- 管理员会话：`/apps/product-encoder/`、`/apps/sales-commission/`、`/apps/knowledge-base/` 均为 200。
- 未登录知识库页面与分类 API：401。
- 管理员知识库页面和分类读取：200。
- 分类直连 POST（无管理员上下文）：403。
- 知识库 API listener：`127.0.0.1:4180`。

## 注意

- 知识库“资料新增、更新、停用、评论”目前沿用其原业务接口，工作台网关保证登录与应用访问；尚未细分到逐个资料对象的所有权策略。
- 工作台左侧导航仍有旧前端 `demo-auth` 映射。服务端网关已强制校验；下一项应将导航可见性和操作级权限迁移到服务端持久化权限表。
- 当前仍按用户要求使用 HTTP/IP；会话 Cookie 未设置 Secure，不适合传输真实敏感业务数据。
